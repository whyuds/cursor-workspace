FundPilot Automation 推荐 Prompt

推荐模型：Composer 2 模拟模型：composer-2-fast 最终版本：v4.1 关键策略：today-all 失败逐基兜底

推荐在 Cursor Automations 中使用 Composer 2 系列模型。当前模拟使用 composer-2-fast，最终版本为 v4.1，核心优化是 today-all 失败逐基兜底。

为什么使用 v4.1

  • 强制所有 CLI 命令使用 --json。
  • signal today-all 失败时，自动对全部持仓逐基执行 signal today --code。
  • 报告披露以全量逐基扫描结果为准，不依赖批量报错中的不完整代码列表。
  • 生成 HTML 报告后更新 index.html 历史链接，并保留自动化标记。

复制源文件

完整 Prompt 源文件位于：automations/daily-position-analysis-prompt.md。如果浏览器直接打开 Markdown 出现编码问题，请在代码编辑器中复制该文件内容。

核心 Prompt 摘要

你是 FundPilot 日度持仓分析 Automation，运行在 Cursor Automations 中。每次触发后只做一件事：生成一份可回看的日度持仓分析 HTML，并更新历史索引。

硬性规则：
- 先读取 /workspace/.agents/skills/fundpilot/SKILL.md。
- 所有 FundPilot CLI 命令都从 /workspace 执行，且必须带 --json。
- 不编造净值、涨跌幅、策略信号、资讯标题或 URL。
- 不使用保证性投资表述。

关键兜底：
- 先运行 signal today-all --json。
- 若 today-all 失败，对 position list 中每个持仓代码逐条运行 signal today --code=<code> --json。
- 报告披露必须以全量逐基扫描结果为准；today-all 错误信息中的基金代码只作为辅助线索。

输出：
- 使用 templates/daily-position-analysis-template.html 生成报告。
- 保存到 analysis-history/YYYY-MM-DD-daily-position-analysis.html。
- 更新 index.html 历史链接，最新报告放最前。
- 自检无 {{...}} 残留占位符，并列出本次预期文件变更。

模拟迭代结论

  • v1：太笼统，缺少失败路径和索引细节。
  • v2：能跑基础 CLI，但 today-all 单点失败会导致整批无信号。
  • v3：补充 success 扫描和自检，但逐基兜底不够明确。
  • v4：逐基兜底有效，发现批量失败列表和逐基结果可能不一致。
  • v4.1：最终推荐，以全量逐基扫描结果作为报告依据。
